# AI-Calendar · Calendar Reminder

[简体中文](README.md) | **English**

“Calendar Reminder” is a Chinese-language desktop scheduling application for Windows 10/11 x64. Core calendar functions, reminders, and standard import/export work offline. Optional AI-assisted import requires internet access and the user's own provider API key. The application does not depend on a browser or Microsoft Office, and its database is stored in the current user's profile by default.

This project is open-sourced under the [MIT License](LICENSE). Third-party dependencies remain subject to their respective licenses.

## Features

- Create, view, edit, and delete schedules. Every schedule entry on the main page has its own delete button, and checkbox selection, multi-select, select-all, and transactional batch deletion are supported.
- Schedule time and reminder time are configured separately and displayed uniformly as `yyyy/MM/dd HH:mm`. Older databases automatically migrate reminder times from the original schedule times.
- Local SQLite persistence, time indexes, duplicate checking, and transactional batch import.
- Checks for reminders due approximately every 25 seconds and displays both a system-tray balloon and a topmost desktop reminder window. Closing the main window keeps the application running in the background.
- Import preview supports editing, unchecking, deleting recognized results, and displaying recognition/duplicate/error states.
- Duplicate entries can be skipped, imported anyway, or used to replace the original schedule.
- Per-user startup-at-login option.
- After automatic startup, reminders that became due while the program was not running are merged into one summary popup.
- Detailed exceptions are written to local logs, while the normal UI only shows concise Chinese error summaries.
- A dedicated API page can configure DeepSeek, Kimi, OpenAI, and Anthropic (Claude), with 2–4 model choices for each provider. Keys are encrypted through Windows Credential Manager.
- AI import first generates a normalized `.xlsx`, then opens the editable import preview. The model compares candidates against all existing schedules in batches and blocks results whose time and task content strongly overlap.

## Technology stack

- C#, .NET 8, WPF, MVVM (CommunityToolkit.Mvvm)
- SQLite (Microsoft.Data.Sqlite)
- ClosedXML and ExcelDataReader (Excel)

- PDFsharp and PdfPig (PDF)

## Development environment and commands

The project currently uses .NET SDK `8.0.423`. If the system `dotnet` installation does not include that SDK, Microsoft's official `dotnet-install.ps1` can be used to install it into an isolated directory, after which that directory's `dotnet.exe` can be invoked explicitly.

```powershell
dotnet restore CalendarReminder.sln
dotnet build CalendarReminder.sln -c Release
dotnet test CalendarReminder.sln -c Release
dotnet publish src/CalendarReminder.App/CalendarReminder.App.csproj -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true -p:DebugType=None -p:DebugSymbols=false -o dist
```

## Data locations

- Database: `%LocalAppData%\CalendarReminder\calendar.db`
- Logs: `%LocalAppData%\CalendarReminder\logs\`
- Non-sensitive API configuration: `%LocalAppData%\CalendarReminder\api-settings.json`
- Normalized Excel files generated by AI import: `%LocalAppData%\CalendarReminder\ai-imports\`

API keys are not written into configuration files. They are stored in the current user's Windows Credential Manager as `CalendarReminder.ApiKey.<provider>` entries.

On first launch, the application automatically creates the required directories, database, tables, and indexes.

## Import and export

Supported import formats: `.xls`, `.xlsx`, `.docx`, `.pdf`, `.pptx`, `.png`, `.jpg`, `.jpeg`.

Supported export formats: `.xlsx`, `.docx`, `.pdf`, `.pptx`, `.png`, `.jpg`. When image output spans multiple pages, files are named using the `filename_01`, `filename_02`, and similar pattern.

For Excel, the importer prioritizes headers such as date, date-time, time, arrangement, content, and task. Word imports prioritize tables while also reading paragraphs. PowerPoint imports text boxes and tables. PDF import first extracts text and renders pages for OCR when text is insufficient. Images always use local Windows OCR. Every recognized result must pass through the preview before being written to the database.

When an imported record contains an explicit year/month/day but no specific hour and minute, the schedule time defaults to `07:30` on that day and the reminder defaults to `07:30` on the previous day. The preview shows the actual reminder time. A month or month-week expression without a year is still marked “Needs confirmation” unless the file provides one unique and unambiguous year context; the application does not invent an absolute date.

Default rules for imprecise dates, all using `07:30`: a year alone maps to January 1 of that year, with the reminder on December 31 of the previous year; a month, beginning-of-month, or early-month expression maps to day 1; mid-month maps to day 13; late-month maps to day 19; end-of-month maps to day 25. Month-based reminders are set one day before the default date. A month without a year only uses these rules when the file contains exactly one clear year context. If no year exists, or multiple different years are present, the result remains “Needs confirmation.” Common Chinese month expressions such as “八月” and related synonyms are supported.

Date ranges are expanded as closed intervals, so both the start and end date produce schedules. For example, `2026年7月20日至22日` creates entries for July 20, 21, and 22. Each entry keeps the same task description and adds a normalized `日期范围：2026/07/20—2026/07/22`. All entries use a reminder time of `07:30` on the day before the left endpoint of the range. Same-month, cross-month, and cross-year ranges are supported.

“Week N of a month” is calculated Monday through Sunday, with the week containing the month's first Sunday treated as week 1. As a result, week 1 may include dates from the end of the previous month. Recognition expands the full seven-day week as a closed interval and applies the date-range behavior described above.

Excel import supports project-plan matrices that use a year heading, month row, week row, and horizontally arranged planning cells. The application combines customer, end customer, product name, project, content, status, issue, and plan text. Date ranges and month-week expressions are expanded into daily entries. When one cell contains multiple date expressions, each is parsed separately. A horizontal week sequence without enough date semantics is still marked for confirmation.

## AI import

The API page supports DeepSeek, Kimi (Moonshot AI), OpenAI, and Anthropic (Claude). Each provider exposes 2–4 current model options. “Claude Code” is a development tool rather than an API provider, so the UI identifies its actual provider as Anthropic. Model names can change as providers release or retire models; if a provider reports that a model does not exist, the model catalog in the application must be updated.

For AI import, the application first extracts text locally from Excel, Word, PDF, PowerPoint, or image files, then sends the text to the selected model to organize it into structured schedules. Candidate schedules are compared against all existing schedules in batches. Results that the model determines to strongly overlap in both time and task are marked “Highly overlapping,” unchecked by default, and forcibly skipped by the database transaction layer. After organization, a normalized Excel file is generated and opened in the existing import preview; the database is not modified until the user confirms the preview.

Before every request, the application displays the provider, model, number of existing schedules, and data range and asks for confirmation. File text, together with schedule time, reminder time, and descriptions from existing schedules, may leave the local computer, may incur API charges, and is subject to the privacy policy of the selected provider. Standard local import sends no data externally.

## OCR and scanned-PDF limitations

- OCR depends on language packs installed in Windows, prioritizing Simplified Chinese while also supporting English and numeric recognition through the user's language list. If no usable language pack exists, the application shows an explicit warning.
- Scanned PDF import depends on Windows.Data.Pdf successfully rendering pages. Encrypted, damaged, extremely large, or unsupported PDFs may fail to import.
- OCR can make mistakes or omit information. OCR results therefore never bypass the preview and write directly to the database; incomplete or ambiguous dates are marked “Needs confirmation.”
- Password-protected Office/PDF files are outside the supported scope.
- AI can improve semantic organization of complex tables, but correctness is not guaranteed. Ambiguous dates still require manual confirmation in the preview. A large number of existing schedules is split across multiple semantic-comparison requests, so latency and cost increase with schedule count.

## Reminders and exit behavior

While running, the application queries approximately every 25 seconds for schedules whose reminder time has arrived and whose reminder has not yet been triggered. Each schedule has independent “schedule date/time” and “reminder date/time” values, and the reminder may be earlier or later than the schedule itself. When due, the application displays both a tray balloon and a topmost desktop popup. After the user acknowledges the popup, `ReminderTriggered = true` is written to prevent repeat reminders. Multiple simultaneously due reminders are displayed in sequence. Clicking the main window's close button only hides it to the system tray and keeps reminder checking active; use the tray icon's “Exit” command to terminate the process.

After each successful reminder query, the application saves a checkpoint. When startup-at-login is enabled, if the next launch detects schedules that became due after the last checkpoint but before the current startup and are still untriggered, it displays one “Schedules due while the computer was off” summary window containing all schedule times, reminder times, and full descriptions. Confirming the summary marks the whole group at once, avoiding a cascade of individual popups. In the event of abnormal power loss, the checkpoint is at most roughly 25 seconds old, so the mechanism also covers reminders that became due shortly before a forced shutdown but had not yet appeared.

## Final application

`dist\日历提醒.exe`

This is a self-contained single-file Windows x64 executable and does not require the user to install a separate .NET Runtime. It can be launched directly.

A portable archive suitable for sending to other Windows 10/11 x64 users is available as `outputs\日历提醒_1.4.2_win-x64_便携版.zip`. The recipient can extract it and launch `日历提醒.exe`.

## Application icon

Version 1.4.2 uses the user-provided blue calendar, clock, and yellow reminder-bell image as the application icon. The project keeps the original PNG and generates a Windows ICO containing 16, 24, 32, 48, 64, 128, and 256 pixel sizes. The same icon is applied to the EXE, main window, edit/import/export/reminder windows, taskbar, and system tray.
